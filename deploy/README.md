# SIBVENT — Docker-развёртывание проекта

## 1. Описание проекта

SIBVENT — веб-приложение, разработанное с использованием React, Vite, Express и PostgreSQL.

Для контейнеризации приложения используется Docker Compose. Взаимодействие между frontend, backend и базой данных организовано через внутреннюю сеть Docker.

## 2. Архитектура проекта

Проект состоит из четырёх основных сервисов:

- **Frontend** — пользовательский интерфейс на React.
- **Backend** — серверная часть на Express.
- **Database** — база данных PostgreSQL.
- **Nginx** — обратный прокси-сервер, обеспечивающий доступ к приложению и HTTPS.

Схема взаимодействия:

```text
Пользователь
     |
     v
   Nginx
  /     \
Frontend  Backend
             |
             v
         PostgreSQL
```

## 3. Используемые технологии

- React
- Vite
- Node.js
- Express
- PostgreSQL
- Docker
- Docker Compose
- Nginx
- GitHub Actions
- GitHub Container Registry (GHCR)

## 4. Docker-сервисы и порты

В проекте используются четыре Docker-сервиса:

Frontend — пользовательский интерфейс приложения. Использует порт 4173.

Backend — серверная часть приложения, обрабатывающая API-запросы. Использует порт 5000.

Database — база данных PostgreSQL, работающая на порту 5432.

Nginx — обратный прокси-сервер, обеспечивающий доступ к приложению по HTTP и HTTPS. Использует порты 80 и 443.

Взаимодействие между сервисами осуществляется через внутреннюю сеть Docker. Пользователь обращается к приложению через Nginx.

## 5. Переменные окружения

Для настройки подключения к PostgreSQL используются следующие переменные:

- `POSTGRES_DB` — название базы данных.
- `POSTGRES_USER` — имя пользователя базы данных.
- `POSTGRES_PASSWORD` — пароль базы данных.
- `DB_HOST` — адрес сервера базы данных.
- `DB_PORT` — порт базы данных.
- `DB_NAME` — название базы данных для backend.
- `DB_USER` — пользователь базы данных для backend.
- `DB_PASSWORD` — пароль базы данных для backend.

Файл `.env` хранится отдельно и не публикуется в GitHub.

## 6. Запуск проекта

Файл Docker Compose находится в отдельной папке `SIBVENT-deploy`.

Для запуска необходимо перейти в эту папку:

```powershell
cd "C:\Users\Аля\Desktop\SIBVENT-deploy"
```

Запуск всех контейнеров:

```powershell
docker compose up -d --build
```

Проверка состояния контейнеров:

```powershell
docker compose ps
```

Просмотр логов:

```powershell
docker compose logs
```

Остановка контейнеров:

```powershell
docker compose down
```

## 7. Проверка работоспособности

Локальный адрес приложения:

`https://sibvent.localhost`

Проверка API:

`https://sibvent.localhost/api/hello`

При успешном подключении к PostgreSQL API возвращает сообщение об успешном соединении и название базы данных.

## 8. CI/CD и публикация Docker-образов

Для автоматизации сборки и проверки проекта используется GitHub Actions.

При отправке изменений в репозиторий выполняются следующие действия:

1. Получение исходного кода.
2. Установка зависимостей Node.js.
3. Проверка кода с помощью ESLint.
4. Сборка frontend.
5. Сборка Docker-образов backend и frontend.
6. Публикация Docker-образов в GitHub Container Registry.

Опубликованные образы:

- `ghcr.io/zbajcfrhev-ux/ui-test/backend:latest`
- `ghcr.io/zbajcfrhev-ux/ui-test/frontend:latest`

## 9. Безопасность

- Пароли и другие конфиденциальные данные хранятся в файле `.env`.
- Файл `.env` исключён из Git.
- SSL-сертификаты и закрытые ключи не публикуются в репозитории.
- Для локального HTTPS используется сертификат mkcert.

## 10. Развёртывание на внешнем сервере

Для размещения приложения на общедоступном сервере потребуется:

- VPS или другой сервер с установленным Docker.
- Настройка DNS и доменного имени.
- Открытие необходимых портов на сервере и в сетевом экране.
- Настройка Nginx для публичного домена.
- Получение действительного SSL-сертификата, например с помощью Let's Encrypt.
- Настройка безопасных переменных окружения.
- Настройка автоматического обновления приложения после публикации новых Docker-образов.

Текущий адрес `sibvent.localhost` предназначен только для локального использования и не обеспечивает доступ к сайту из интернета.

Также настроен процесс CI/CD с использованием GitHub Actions и публикацией Docker-образов в GitHub Container Registry.
